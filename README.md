# paper/ — figures & sensitivity tables for the change-in-mobility-during-COVID paper

Self-contained publication package: the flat data behind every figure, the plotting code, a
reference implementation of every metric, and a notebook that reproduces the whole figure set.
Everything here (except `extract_figure_data.py`) is independent of the rest of this repository —
no `src/`, no S3, no `ParquetStore`.

```
paper/
  README.md                          this file
  setup_mpl.py                       shared matplotlib/seaborn styling (fonts, colours, DPI, save())
  metrics_change_mobility_covid.py   reference implementation of every metric (no S3/pipeline burden)
  plot_change_mobility_covid.py      every figure (figure_1 .. figure_13), reads data/figure_<i>.csv
  plot_change_mobility_covid.ipynb   notebook that calls each plot one by one
  extract_figure_data.py             SERVER-SIDE script: consolidated results -> data/figure_<i>.csv
  data/
    figure_1.csv  ...  figure_13.csv               one row per plotted data point, see below
    <feature>_t_threshold_{8,24}_MA-CA.csv          t_threshold sensitivity tables (both regions)
```

## Quick start — reproducing the figures

1. `pip install numpy pandas matplotlib seaborn scipy polars` (only needed for `data/` generation,
   see step 0 below; the notebook itself only needs `numpy pandas matplotlib seaborn scipy`).
2. Open `plot_change_mobility_covid.ipynb` **from inside this `paper/` directory** (so the relative
   `data/`/`figures/` paths resolve) and run all cells. Each cell reads the matching
   `data/figure_<i>.csv`, redraws the figure, saves a PNG to `figures/figure_<i>.png`, and displays
   it inline.
3. Alternatively, from the command line:

   ```
   python plot_change_mobility_covid.py                       # every figure
   python plot_change_mobility_covid.py --only figure_1 figure_8   # a subset
   ```

## Step 0 — regenerating `data/figure_<i>.csv` (server-side only)

The `figure_1.csv .. figure_13.csv` files are **not regenerated by this repository checkout alone**
— they are extracted from the consolidated `check_*`/`distance_check` result trees under
`milestones_analysis/<region>/...`, which only exist on the machine where the pipeline was actually
run. If those CSVs are already present in `data/`, skip this step.

To (re)build them, on the server, from the repository root:

```
python paper/extract_figure_data.py
```

This requires that the following have already been run for `--region CA --np 20 --t-threshold 1`
and `--region MA --np 20 --t-threshold 1` (all figures are at `t_threshold = 1`):

* `src/check_rg_krg/main_computation_rg_krg.py`        (figure_2, figure_9)
* `src/check_entropy/main_computation_entropy.py`      (figure_6, figure_13)
* `src/check_frequency_st/main_computation_frequency_st.py`  (figure_3, figure_10)
* `src/distance_check/main_computation_distance_new.py`      (figure_1, figure_8)
* `src/check_gonzalez/main_computation_gonzalez_old.py`      (figure_4/5, figure_11/12)
* `src/check_rg_weekly/main_computation_rg_weekly.py`        (figure_7, CA only)

The `<feature>_t_threshold_{8,24}_MA-CA.csv` sensitivity tables come from
`milestones_analysis/sensitivity_analysis.json`, built by running (both regions, each t_threshold):

```
python src/sensitivity_analysis.py --region CA --t-threshold 8
python src/sensitivity_analysis.py --region MA --t-threshold 8
python src/sensitivity_analysis.py --region CA --t-threshold 24
python src/sensitivity_analysis.py --region MA --t-threshold 24
```

`extract_figure_data.py` reuses the exact data-preparation functions the `check_*/plot_*.py` scripts
already use, so every row in `data/figure_<i>.csv` matches what the corresponding figure plots — it
does not recompute anything itself. Run `python paper/extract_figure_data.py --only figure_1
figure_8 sensitivity` to (re)build a subset; anything not yet computed on the server is skipped with
a message telling you which `main_computation_*.py` to run first.

### `data/figure_<i>.csv` column contracts

* **figure_1 / figure_8** (`rg_and_dist`) — `panel` (`radius_of_gyration`|`jump_length`), `period`,
  `bin_center`, `pdf`, `fit_alpha`, `fit_sigma`, `fit_xmin`, `fit_fraction` (fit columns only
  populated for the `jump_length` panel — a power-law fit to the jump-length tail).
* **figure_2 / figure_9** (`rg_krg`) — `period`, `k`, `rg_km`, `krg_km`, `density`. Sparse: cells
  with zero density are omitted (the full grid is a fixed 40x40 bins over `[0.1, 1500]` km on both
  axes, reconstructed by the plot code).
* **figure_3 / figure_10** (`st_and_frequency`) — `panel` (`st`|`frequency`), `period`, `time_step`,
  `mean_st`, `std_st` (S(t) panel only), `rank`, `mean_frequency` (frequency panel only).
* **figure_4 / figure_11** (`gonzalez`) — `period`, `x_norm`, `y_norm`, `count`. Sparse: zero-count
  cells omitted (fixed 40x40 grid, `x_norm` in `[-1.5, 1.5]`, `y_norm` in `[-2.2, 2.2]`).
* **figure_5 / figure_12** (`sigmaxy`) — `period`, `axis` (`sigma_x`|`sigma_y`), `bin_center`, `pdf`,
  `mean_km`, `mean_pct_change_vs_baseline` (percent change vs. the pre-restriction period; `NaN` for
  the baseline period itself).
* **figure_6 / figure_13** (`entropy`) — `period`, `entropy_type`
  (`random_entropy`|`uncorrelated_entropy`|`real_entropy`|`scaled_entropy`), `bin_center`, `pdf`.
* **figure_7** (`weekly_rg`, California only) — `panel` (`rurality`|`party`), `week`, `stratum`
  (`rural`/`urban` or `Democratic`/`Republican`), `mean_rg`, `std_rg`.

### Sensitivity tables (`<feature>_t_threshold_{8,24}_MA-CA.csv`)

One CSV per (feature, t_threshold), each with a `region` column so California and Massachusetts sit
in the same file — mirroring the seven features in `src/sensitivity_analysis.py` /
`src/sensitivity_analysis_latex.py`:

* `distance_powerlaw` — jump-length power-law fit (`alpha`, `alpha_sigma`, `xmin_km`,
  `tail_fraction`) per region/period.
* `entropy_peak` — PDF peak (mode) per region/period/entropy type.
* `frequency_top2_pct` — combined visitation share of the two most-visited locations, per
  region/period.
* `rg_distance_crossing` — the radius-of-gyration PDF crossing point (`r_g_star_km`) and area between
  curves for the restriction period vs. pre/post, per region.
* `rg_krg_bin0_percentile` — 95th percentile of `R_g` for users whose k-`R_g` falls in the
  near-zero bin, per region/period/k.
* `sigmaxy_pct_change` — mean sigma_x/sigma_y (km) and percent change vs. baseline, per
  region/period.
* `st_exponent_mu` — S(t) exploration-curve power-law exponent, per region/period.

Figures 1–13 are only produced at `t_threshold = 1`; these sensitivity tables are how the paper shows
the same qualitative story holds at `t_threshold = 8` and `24` hours, without shipping full figure
data for every threshold.

## `metrics_change_mobility_covid.py`

A from-scratch reference implementation of every metric used above — radius of gyration, k-radius of
gyration, entropy (random/uncorrelated/real via the LZ78 estimator), jump lengths/total distance,
Gonzalez PCA trajectory shape (both the current formula and the specific legacy formula that actually
produced figures 4/5/11/12 — see its docstring for the three documented quirks it deliberately
reproduces), the S(t) exploration curve, location frequency/rank, weekly radius of gyration, plus the
small log-log PDF and power-law-fit helpers the plots use. Each function documents its expected input
schema (a `polars.DataFrame` of already-preprocessed stop points) and formula in its docstring — read
it if you want to understand *how* a number was computed without wading through the production
pipeline's S3/checkpoint/`ParquetStore` machinery.

## Regenerating this package after a repo change

If `src/check_*`/`src/distance_check`/`src/sensitivity_analysis.py` change in a way that alters what
gets plotted, re-run `extract_figure_data.py` on the server, copy the refreshed `data/*.csv` here (or
just re-run it in place if you're already working in a checkout on the server), and re-run
`plot_change_mobility_covid.ipynb` (or the CLI) to refresh `figures/*.png`.
